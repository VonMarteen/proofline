# PROOFLINE H5 — Email System

Version: v0.2.15-H5-EMAILS

## Objective

All transactional email emitted through the `SEND_EMAIL` outbox is rendered by one versioned template registry in the worker. The API may provide business content, locale and correlation IDs, but visual HTML generation is centralized.

## Contract

Every delivered message has:

- category
- templateId
- templateVersion
- family
- HTML body
- plain-text body
- provider/local messageId
- safe completion metadata in Outbox
- `EMAIL_DELIVERED` / `EMAIL_DELIVERY_FAILED` audit evidence

Recipient addresses, OTP codes, participant tokens and free-text bodies are not persisted in completed Outbox payloads.

Failed jobs retain their original payload so an explicit Control retry remains possible. Successful jobs are scrubbed.

## Registered families

- AUTH — client/internal OTP
- ACCESS — client/internal activation
- ASSESSMENT — participant invitations
- REPORTING — report distribution
- SUPPORT — customer replies, information requests and SLA escalations
- COMMERCIAL — demo/start/contact and evaluation conversion
- BILLING — invoice/payment-status templates are registered; no automatic billing email trigger is invented where the product does not currently emit one
- SYSTEM — safe fallback for an unregistered category

## Local QA

Run:

```bash
pnpm email:check
```

Then use Mailpit (`http://localhost:4280`) for visual review of emails generated by real flows. Production SMTP/provider configuration is deliberately outside this local gate.
